no session

POST /api/register

username 3–32 characters (a-z 0-9 . _ -), stored as lowercase · password 8–72 bytes, no control characters · body max 4 KiB · 5 requests per IP, one token every 12 s

POST /api/login

same field rules as register · 5 requests per IP, one token every 12 s · the answer never says which of the two was wrong

GET /api/session

Authorization: Bearer <token> · 10 requests per IP, one token every 12 s

no token stored

POST /api/music/upload

form field named file · audio only: mp3 wav m4a ogg opus flac aac · max 500 MiB · 3 requests per IP, one token every 30 s

GET /api/music

id and title for every song, ordered by id · 10 requests per IP, one token every 12 s

GET /api/music/{id}

a positive song id (digits only) · the file in 32 KiB chunks with a flush after each · 10 requests per IP, one token every 10 s · errors only before the first byte

POST /api/playlists

a playlist belongs to you, not to the shared library · name max 100 characters, control characters dropped, names are not unique · 10 requests per IP, one token every 12 s

GET /api/playlists/{id}

only your own · another user's playlist answers 404 as "not in your playlists" · positions are 1..n and stay contiguous after a remove · titles come from the library row

POST /api/queue

source is playlist, library or track · filling replaces the queue · a queue stores only songs and order, never what filled it · 10 requests per IP, one token every 12 s, its own bucket

Not implemented yet

POST /api/logout answers 404. Range on GET /api/music/{id} is not implemented, so a Range request gets the whole file with 200 — a player that seeks needs it. Renaming a playlist and moving a song to another position are planned in api-docs.md.
